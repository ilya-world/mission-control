# Mission Control MVP — Product/Tech Specification

## 0. Вводные

**Mission Control** — онлайн-планировщик задач в браузере (desktop web). Ключевая идея: пользователь ведёт дерево задач (цели/проекты/задачи/подзадачи), а система показывает **To-Do** как список актуальных **Активных действий** — следующих шагов, которые можно выполнять прямо сейчас.

**Ограничения MVP:**

- Один пользователь (без шаринга/совместной работы).
- Только desktop web.
- Без внешних интеграций.
- Без шаблонов стартовой структуры.
- Внешние файлы — только как URL (без загрузки файлов).

---

## 1. Термины

- **Задача (Task)** — базовая сущность, элемент дерева.
- **Схема (Outline)** — иерархический список (дерево) задач.
- **To-Do** — линейный список задач, сформированный из дерева по правилам вида.
- **Активные действия** — основной вид To-Do, показывающий доступные к выполнению задачи по правилам активности.
- **Вид (View)** — сохранённая конфигурация отображения (фильтр, группировка, сортировка, колонки).
- **Группа видов** — папка для видов.
- **Область (Area)** — вкладка-рабочее пространство, где сохраняется выбранный вид и локальные настройки отображения.
- **Контекст (Context)** — категория/ситуация (иерархическая). К задаче можно назначить несколько контекстов.
- **Текстовый тег** — одна строковая метка на задачу.
- **Флаг** — визуальная метка из настраиваемого списка (с иконкой).
- **Избранное** — звездочка на задаче.

---

## 2. Общее поведение приложения

### 2.1 Автосохранение

- Любые изменения (создание/редактирование/перемещение/завершение) сохраняются автоматически.
- При ошибке сохранения показывается понятное уведомление и возможность повторить.

### 2.2 Горячие клавиши (минимум)

MVP поддерживает базовые хоткеи:

- Создать задачу.
- Создать подзадачу.
- Завершить/вернуть.
- Поиск.
- Переключение между Схемой и To-Do.

> Точный набор и комбинации — на усмотрение реализации, но должны быть настраиваемыми как минимум на уровне списка «Actions».

---

## 3. Основные экраны и компоненты

### 3.1 Экран «Схема» (Outline)

**Назначение:** управление деревом задач.

Функции:

- Отображение дерева с разворачиванием/сворачиванием узлов.
- Создание: задача, подзадача, проект, папка.
- Редактирование названия инлайн.
- Drag-and-drop:
  - перенос задачи внутри дерева (смена родителя и позиции среди соседей),
  - изменение порядка среди братьев/сестёр.
- Завершение:
  - завершить задачу,
  - завершить задачу вместе с подзадачами (массово),
  - вернуть из завершённых.
- Быстрое перемещение через диалог (выбор нового родителя по дереву + позиция).

### 3.2 Экран «To-Do»

**Назначение:** выполнение задач.

Функции:

- Отображение списка задач выбранного вида (по умолчанию — «Активные действия»).
- Завершение/возврат задачи из списка.
- Быстрое открытие панели свойств выбранной задачи.
- Поддержка фильтров/группировки/сортировки согласно виду.

### 3.3 Левая панель: «Области» и «Виды»

**Области (Areas):**

- Вкладки-рабочие пространства.
- В каждой области хранится:
  - выбранный вид,
  - локальные настройки отображения (например, скрытие завершенных).
- Можно создать/переименовать/удалить область.

**Виды (Views):**

- Дерево видов и групп видов.
- Операции: создать, сохранить изменения, переименовать, дублировать, удалить, перетащить для изменения порядка.

### 3.4 Панель свойств задачи (Inspector)

**Расположение:** правая выдвижная панель или модальное окно.

Вкладки:

- Свойства.
- Заметки (Markdown).

## 4. Модель задач (поля и правила)

### 4.1 Типы задач

Задача может быть одного из типов:

- Обычная задача.
- Проект (узел-органайзер с подзадачами).
- Папка (контейнер для группировки).
- Цель (goalType): week / month / year.

Тип влияет на попадание элемента в «Активные действия» (см. раздел 5).

### 4.2 Базовые поля

- Title (обязательное).
- Notes (Markdown).
- Completed (bool).
- CreatedAt, UpdatedAt.
- ParentId (null для корня).
- OrderIndex (позиция среди соседей).

### 4.3 Контексты, тег, флаг, избранное

- Contexts: множество контекстов (many-to-many). Контексты иерархичны.
- TextTag: ровно один строковый тег на задачу.
- FlagId: опциональная ссылка на флаг.
- IsFavorite: звездочка.

**Требования к контекстам:**

- Справочник контекстов с поддержкой иерархии.
- Автоподсказка и быстрый поиск.
- Создание нового контекста из поля ввода.

**Флаги:**

- Справочник флагов; у каждого:
  - name,
  - icon (SVG/PNG),
  - order.

### 4.4 Даты: Начало и Срок

- StartAt (Начало) — когда задача становится видимой для выполнения.
- DueAt (Срок) — дедлайн.

**Правила:**

- Если задан StartAt, задача не может быть активной до StartAt.
- Ввод дат поддерживает RU «естественный язык» (например: «завтра 14:00», «через 30 минут», «в пятницу»).
  - Парсер устойчив к вариантам написания.
  - Если распарсить нельзя — подсветить ошибку и не применять.

**Наследование дат:**

- По умолчанию подзадачи могут наследовать даты родителя (настраиваемо на уровне задачи через переключатель).
- Команда «Наследовать даты родителя» сбрасывает пользовательские даты подзадачи и включает наследование.

### 4.5 Напоминания

**Поля:**

- ReminderEnabled (bool).
- ReminderAt (datetime).
- SnoozePreset (опционально).

**Поведение:**

- Когда наступает ReminderAt, приложение показывает:
  - внутреннее модальное окно «Напоминания» со списком сработавших напоминаний,
  - браузерное уведомление (при наличии разрешения).
- В окне напоминания доступны действия:
  - открыть задачу,
  - выключить напоминание,
  - отложить (snooze) на preset (например 10 мин, 30 мин, 1 час).

### 4.6 Повторяющиеся задачи

- Поддержка повторов через диалог «Повтор…».
- Минимальные режимы повторения: daily / weekly / monthly / yearly.
- В каждый момент времени существует один «текущий» экземпляр повторяющейся задачи.
  - Следующий появляется после завершения текущего.

**Команда «Пропустить повтор…»:**

- Пропустить только текущий повтор (сдвинуть на следующий по правилу).

### 4.7 Зависимости

- У задачи может быть список зависимостей (ссылки на другие задачи).
- Режим разблокировки:
  - ALL — активируется после выполнения всех зависимостей.
  - ANY — активируется после выполнения любой зависимости.
- Отложенная зависимость:
  - DelayAfterDone (duration),
  - если ALL — отсчет от последней завершенной зависимости,
  - если ANY — отсчет от первой завершенной зависимости.

### 4.8 Оценка времени

**Поля:**

- TimeRequiredMin (мин).
- TimeRequiredMax (мин).

**Использование:**

- Фильтрация To-Do по доступному времени (см. виды).

### 4.9 Проекты и статус

Проект имеет дополнительное поле:

- ProjectStatus: NotStarted / InProgress / Waiting / Completed.

Статус меняется вручную.

## 5. Правила формирования «Активных действий»

«Активные действия» — главный список To-Do в MVP.

Задача считается **активной** и попадает в список, если одновременно:

1. Задача не завершена.
2. Задача не является папкой.
3. Задача не является проектом.
4. Задача является листом — у нее нет незавершенных подзадач.
5. Если задан StartAt — StartAt ≤ текущее время.
6. Зависимости выполнены согласно режиму ALL/ANY и выдержан DelayAfterDone, если он задан.
7. Если у любого предка включено «Выполнение подзадач по порядку», то активной является только первая по порядку незавершенная задача среди братьев внутри этого предка.

### 5.1 Выполнение подзадач по порядку (для любого узла)

- У любого узла дерева (задача/проект/цель/папка) может быть флаг SequentialModeEnabled.
- Если он включен, то среди его прямых дочерних задач активна только первая незавершенная (по OrderIndex).
- Остальные дочерние задачи считаются заблокированными этим правилом и не попадают в «Активные действия», даже если они листья.

---

## 6. Виды: фильтрация, группировка, сортировка, колонки

### 6.1 Фильтры (минимальный набор)

Виды поддерживают фильтры по:

- Контексты (включая выбор контекста с учетом иерархии).
- Текстовый тег.
- Флаг.
- Избранное.
- Тип задачи (задача/проект/папка/цель).
- Статус проекта.
- Наличие/отсутствие дат.
- Диапазон StartAt / DueAt.
- Диапазон TimeRequiredMin/Max.
- Завершенные/незавершенные.

### 6.2 Группировка

- По контексту.
- По флагу.
- По тегу.
- По типу.
- По статусу проекта.
- Без группировки.

### 6.3 Сортировка

MVP: сортировка в видах может быть простой и явной:

- По названию.
- По сроку (DueAt).
- По началу (StartAt).
- По времени (TimeRequiredMin/Max).
- По ручному порядку (OrderIndex).

### 6.4 Колонки (минимальный набор)

- Title.
- DueAt.
- StartAt.
- Contexts.
- Tag.
- Flag.
- TimeRequiredMin/Max.
- ProjectStatus (если элемент — проект).

---

## 7. Скрытие завершенных

Глобальная настройка вида/области:

- Скрывать завершенные задачи.

Достаточно простого варианта «показывать/скрывать». Cutoff по дате завершения не требуется.

---

## 8. Поиск

- Глобальный поиск по: Title, Notes, Tag.
- Результаты позволяют:
  - перейти к задаче в дереве,
  - открыть задачу в инспекторе.

---

## 9. Импорт/экспорт (минимум)

- Экспорт данных в JSON (бэкап).
- Импорт JSON (восстановление).
- Экспорт текущего To-Do в CSV.

---

## 10. Нефункциональные требования

- Совместимость: последние версии Chrome/Edge/Firefox.
- Производительность:
  - виртуализация списков (дерево и To-Do) для больших объёмов,
  - основные операции (скролл, выбор, открытие инспектора) должны быть отзывчивыми.
- Надежность:
  - автосохранение,
  - корректная работа при потере сети: показать статус, очередь изменений (минимально — блокировать с уведомлением).

---

## 11. Критерии приемки (MVP)

1. Пользователь может создать дерево (задачи/подзадачи/проекты/папки/цели), менять порядок и родителя drag-and-drop.
2. Экран To-Do показывает «Активные действия» по правилам раздела 5.
3. Работает режим «Выполнение по порядку» для любого узла (раздел 5.1).
4. Работают StartAt и DueAt, включая блокировку по StartAt.
5. Работают напоминания (модальное окно + browser notifications + snooze).
6. Работают повторяющиеся задачи в минимальных режимах + «пропустить повтор».
7. Работают зависимости ALL/ANY и DelayAfterDone.
8. Работают контексты (множественные, иерархия), тег (один), флаг, избранное.
9. Работают виды: создать/сохранить/дублировать/удалить, фильтры/группировка/сортировка/колонки.
10. Работает поиск.
11. Работает экспорт/импорт JSON и экспорт To-Do в CSV.
